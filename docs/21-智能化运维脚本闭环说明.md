# 🛡️ 智能化运维脚本闭环说明

> 本文是「看门狗挂载 → 周期探测 → 次晨聚合」运维闭环的**设计与实测文档**。
> 补齐 2026-10-05 盘点确认的三处断点：①看门狗未挂载（B4）②JSONL「次晨可聚合」承诺无兑现件 ③agent 网关不在探活矩阵。

## 一、全局链路视图（脚本矩阵 × 设备链路 × 运维挂载点）

```text
┌─ 设备链路 ────────────────────────────────────────────────────────────┐
│  Mac M4 Max 128GB（本机 · h3-m4 env）                                  │
│  ├─ 工作台 console 3030/3031（Vite+Hono，dev.mjs 编排）                │
│  ├─ agent 网关 8300（会话式常驻：B2/漫剧会话时启动）                    │
│  ├─ NAS（archive_to_nas 双速归档 · .nas_pending 待队列自愈）           │
│  └─ 线上 https://h3.yyc3.top（Pages 落地页）                           │
├─ 运维挂载点 ──────────────────────────────────────────────────────────┤
│  08:10 cron  reconcile_batches（僵尸收敛）                             │
│  22:00 cron  nightly_run（夜间批量：生成→归档→④.5 演进统计→④.6 看门狗聚合）│
│  22:10 cron  video_task_runner（第五能力空闲领取）                     │
│  600s  launchd com.yyc3.console-watch（看门狗 landing-only 探测）★新增 │
├─ 数据流 ──────────────────────────────────────────────────────────────┤
│  console_health_check ──每探次──▶ logs/console_watch.jsonl            │
│       ▲                                    │                          │
│       │ launchd 600s 周期                  │ nightly ④.6 聚合         │
│       │                                    ▼                          │
│  install_watchdog.sh               logs/nightly_*_b*.md 次晨报告       │
└───────────────────────────────────────────────────────────────────────┘
```

**职责边界**：看门狗只观测不干预（退出码 0/1/2 供上层钩子）；夜间批量仍由 nightly_run 独占生成窗口；agent 网关非常驻——探活降级记录不告警。

## 二、缺口 → 补全对照

| # | 断点（盘点确认） | 兑现件 | 闭环方式 |
| - | ---- | ---- | ---- |
| 1 | B4：cron 挂载被 setuid crontab 特权写阻断（沙箱/受限环境 3 次挂死） | `install_watchdog.sh` | **launchd 用户域**（gui/$UID，无 crontab 依赖）+ cron 备选保留 |
| 2 | JSONL 落盘但「次晨报告可聚合」无兑现件 | `aggregate_watch_report.py` | nightly_run.sh ④.6 挂载，Markdown 段嵌入次晨报告 |
| 3 | agent 网关（引擎层心脏）不在探活矩阵 | `console_health_check.py` P3 探点 | `record.agent` 记录 ok/claim_ready/transport；非常驻降级不判失败 |

## 三、用法手册

### 3.1 install_watchdog.sh（挂载/状态/回滚）

```bash
bash scripts/pipeline-tools/install_watchdog.sh               # 安装/更新（幂等）+ 自检 + kickstart 试跑
bash scripts/pipeline-tools/install_watchdog.sh --status      # 挂载状态（state/runs/最近探测）
bash scripts/pipeline-tools/install_watchdog.sh --uninstall   # 完整回滚（bootout + 删 plist，零残留）
H3_WATCH_INTERVAL=300 bash ... install_watchdog.sh            # 自定义周期（默认 600s ≙ cron */10）
```

**行为细节**：
- **前置自检分级**：试跑 exit 1（本地探活失败）阻断安装；exit 2（线上 TTFB 抖动）**放行并提示**——持续观测抖动正是挂载目的（v1.0.0 实测曾误阻断，已修）
- **兼容性**：`launchctl bootstrap gui/$UID` 优先，旧 macOS 回退 `load -w`；幂等（先卸后装）
- plist 关键项：`RunAtLoad`（安装即首跑）+ `StartInterval 600` + 显式 PATH（规避 cron PATH 惯性坑，同 nightly ③ 事故口径）

### 3.2 aggregate_watch_report.py（次晨聚合）

```bash
python3 scripts/pipeline-tools/aggregate_watch_report.py            # 近 24h → Markdown（nightly ④.6 调用形）
python3 scripts/pipeline-tools/aggregate_watch_report.py --hours 168  # 近 7 天
python3 scripts/pipeline-tools/aggregate_watch_report.py --json       # 机器可读
```

聚合口径：探测次数/模式分布（full vs landing-only）、health/sse 失败计数、agent 网关 ok/seen、线上 P95 均值/峰值 + warn 次数（阈 5s 与看门狗同源）。坏行（半行 JSON）跳过不炸。

### 3.3 agent 探点（看门狗 v2 增量）

full 模式默认探 `AGENT_URL`（env 可覆盖，默认 `http://127.0.0.1:8300`）`/api/healthz`：

```json
"agent": {"ok": true, "claim_ready": true, "transport": "inmemory", "seconds": 0.004}
```

**设计约束**：网关会话式常驻（B2/漫剧会话才启动）——`ok:false` 仅记录、**不参与退出码判定**，避免未起网关时每 10 分钟误报。`--landing-only` 模式不带探点（保持零误报口径）。

## 五、回滚与故障处置

```bash
# 完整回滚（不留系统残留）
bash scripts/pipeline-tools/install_watchdog.sh --uninstall
# 挂载异常排查三步
launchctl print gui/$(id -u)/com.yyc3.console-watch | grep -E "state|last exit"
tail -20 logs/console_watch_launchd.log          # launchd 侧 stdout/stderr
plutil -lint ~/Library/LaunchAgents/com.yyc3.console-watch.plist   # plist 语法
```

| 症状 | 处置 |
| ---- | ---- |
| `--status` 报未挂载但 plist 存在 | `bootstrap` 失败回退链未生效 → 手动 `launchctl load -w <plist>` |
| JSONL 长时间不增长 | 查 `console_watch_launchd.log`；多为网络全不可达（样本 -1 → exit 1 记录） |
| 线上 P95 持续 >5s | 观测基线告警（exit 2，不干预）——数据驱动 CDN 决策，见 docs/17 §5.3 |

## 六、cron 备选与常态化约定

**cron 备选**（launchd 不可用环境；注意受限执行环境下 setuid crontab 写会挂死）：

```bash
(crontab -l 2>/dev/null; echo '*/10 * * * * cd /Users/yanyu/YYC-Cube/YYC3-MiniMax-H3 && /opt/miniconda3/envs/h3-m4/bin/python scripts/pipeline-tools/console_health_check.py --landing-only --quiet >> logs/console_watch_cron.log 2>&1') | crontab -
```

**常态化约定**（对齐 docs/09 §2.3）：新增运维脚本必须 ①幂等 ②可回滚 ③退出码契约写入 docstring ④若落 JSONL，同步在本文 §三登记聚合口径。
