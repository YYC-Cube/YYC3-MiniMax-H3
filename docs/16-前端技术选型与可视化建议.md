# 前端技术选型与可视化建议（H3 生产面板 v2）

> 目标：为「生产闭环」可视化面板（docs/生产闭环 04/06 蓝图的现实化）选定技术栈与构建路径，替换/升级现有 `dashboard/data/index.html` 单文件面板。

---

## 一、需求画像（选型前提）

| 维度 | 现状与约束 |
| ---- | ---------- |
| 数据源 | NAS `dashboard/data/batches.json`（`batchesPayloadSchema` envelope，no-store 直读）；后续接 agent 网关 `/api/tasks`（写操作，claim 鉴权） |
| 部署 | NAS 网关 Nginx 静态目录 `/h3-dashboard/`，**纯静态可行性已验证**（生产闭环 04 篇）；dev 端口 3030 起（团队规范） |
| 功能 | 批次 KPI、趋势图、质检分布、列表+详情弹窗（06 篇蓝图已定）；演进：任务下发、漫剧六阶段编排可视化 |
| 团队栈 | Next.js + React + shadcn/ui + Radix + pnpm（既定） |
| 契约 | zod 双端契约已存在（pipeline_auto ⑤' 导出 ↔ 面板解析），**前端必须与 Python 侧同构** |

## 二、全网同类型开源应用综合分析

### 2.1 阵营一：AI 生成类 WebUI（同业务域）

| 项目 | 技术栈 | 前端形态 | 成熟度 | 对本项目启示 |
| ---- | ------ | -------- | ------ | ------------ |
| ComfyUI | Python + **自研 Vue 前端** | 节点图 SPA | 极高（AI 生成 UI 事实标准，Pinokio v3.7 首推） | 节点图是工作流编辑器范式，H3 面板是**监控/运营**范式——不照搬节点图，但其「manifest/工作流 JSON 单一事实源」理念与 H3 manifest 铁律同源，值得对齐交互（批次=可展开节点） |
| Automatic1111 | Python + **Gradio** | 生成式表单 | 高（存量大） | Gradio 开发快但定制天花板低、SSR/组件生态弱——**排除** |
| InvokeAI | Python + **React/TypeScript** | 现代 SPA | 高 | React 阵营在 AI 生成工具中的主流化佐证，支持选 React |
| Pinokio | Electron + 浏览器壳 | 应用商店容器 | 高 | 「一键安装/运行」封装思路可借鉴到 Mac 节点 onboarding（生产闭环 02 篇） |
| Fooocus | Gradio | 极简生成 | 中 | 再次印证 Gradio 适合一次性工具，不适合运营面板 |

**阵营结论**：AI 生成工具的前端已收敛为「React/SPA 主流 + Vue 节点图特例 + Gradio 快速原型」三极；H3 属于**生产运营监控面板**，应向 Dashboard 阵营看齐而非生成工具阵营。

### 2.2 阵营二：Dashboard/数据可视化（2026 主流格局）

| 项目 | 模式 | 基座 | GitHub | 成熟度评级 | 适配度 |
| ---- | ---- | ---- | ------ | ---------- | ------ |
| **shadcn/ui** | copy-paste（源码入仓、零锁死） | Radix UI → 2026-07 起默认 Base UI | 最高 | ★★★★★（Next.js 生态默认选择） | **最高**——团队既定栈 |
| **Tremor** | copy-paste 组件 + Blocks | Recharts | ~3.4k | ★★★★★（Vercel 背书；2026 Blocks 300+ 全免费开放） | **最高**——KPI/Tracker/图表即 H3 面板词汇表 |
| Ant Design Pro | 模板全家桶 | antd 6 | 38.2k | ★★★★（企业级最稳但重） | 中——引入整套设计体系，超出面板需要 |
| Refine | CRUD 框架 | — | ~30k | ★★★★（CRUD 重型应用首选） | 低——非 CRUD 场景 |
| Mantine / MUI | 组件库 | — | 30k+ / 95k+ | ★★★★ | 低——锁死式依赖，与 copy-paste 哲学相悖 |
| Recharts | 图表引擎 | 自身即引擎 | ~26k | ★★★★★（Tremor/shadcn Charts 共同底座） | 高——作为引擎被 Tremor 引入 |
| TailAdmin 等模板 | 现成骨架 | Tailwind v4 + Vite | 1.2k | ★★★ | 中——可借鉴布局，骨架自建有 shadcn 生态冗余 |

**阵营结论**：2026 年分析型仪表盘的最短路径是 **shadcn/ui（组件）+ Tremor（图表块，Recharts 引擎）**，二者同为 copy-paste 模式——源码入仓、零运行时依赖、与 Tailwind v4 同源，与团队栈完全对齐。

## 三、YYC-CUBE-HUB.html 参照审计（本组织资产）

| 项 | 实测 |
| ---- | ---- |
| 规模 | 单文件 121,865 字节（119KB） |
| 技术指纹 | **React（18 处）+ Tailwind + Three.js + localStorage 主题防 FOUC** |
| 形态 | 零构建单 HTML（CDN 引入），「94 仓库矩阵操作中心」 |
| 优点 | 零部署成本、双击即开、主题系统完整、动画层（Three.js） |

**可借鉴**：单文件模式的「零运维」哲学与 H3 面板 NAS 静态部署天然契合；主题防 FOUC 模式、渐变 SVG favicon 等细节可直接移植。

**天花板**：119KB 单文件 = 无类型/无组件拆分/无单测/多人协作冲突率高——适合**门户/展示页**，不适合 H3 面板这类**契约驱动 + 持续演进**的生产工具。结论：HUB 模式作为「宣传门户」保留；面板 v2 走工程化构建。

## 四、三方案对比与推荐

| 维度 | 方案 A：Next.js + shadcn/ui + Tremor（**推荐**） | 方案 B：Vite SPA + shadcn/ui + Recharts | 方案 C：单文件蓝图增强（06 篇路线） |
| ---- | ---- | ---- | ---- |
| 构建 | `output: 'export'` 纯静态产物 | `vite build` 纯静态产物 | 无构建 |
| 契约共享 | zod schema 同构提取为包，双端 import | 同左 | 手写解析（现状） |
| 组件生态 | shadcn 全量 + Tremor Blocks 300+ | shadcn + 手写图表 | 原生 DOM |
| 后续任务下发/编排可视化 | App Router API route 预留（NAS 反代 + claim） | 需另起 BFF | 不可行 |
| 构建/维护成本 | 中 | 低 | 极低（但演进成本递增） |
| 五维评分（架构/质量/功能/性能/演进） | 9.3 | 8.4 | 6.0 |

### 推荐栈（方案 A 定型）

```
Next.js 15/16 (App Router, output:'export')  +  TypeScript strict
├─ UI      shadcn/ui（CLI 拉取，Radix/Base UI 基座，Tailwind v4）
├─ 图表    Tremor Blocks（Recharts 引擎）——KPI 卡/趋势/质量分布/Tracker
├─ 数据    TanStack Query（no-store 轮询 + 降级）+ zod 运行时校验
├─ 契约    @yyc3/h3-contracts 包（batchesPayloadSchema 单一事实源，Python/TS 双端生成或手工对齐+CI 校验）
└─ 部署    pnpm build → out/ → NAS /h3-dashboard/（04 篇模式）；dev: pnpm dev -p 3030
```

**不推荐**：Gradio（部署/生态不契合）、AntD Pro 全家桶（重量溢出）、继续单文件（演进天花板）。

## 五、落地路线（四阶段）

| 阶段 | 交付 | 验收 |
| ---- | ---- | ---- |
| P0 契约包 | `@yyc3/h3-contracts`：envelope + 批次单元 zod schema 提取；CI 加「TS↔Python 字段一致性」校验 | 改 schema 双端同时编译失败（而非运行期） |
| P1 面板 MVP | 批次 KPI + 趋势 + 质检分布 + 列表/详情（06 蓝图的现实化），静态导出部署 NAS。**✅ 起板完成（2026-09-26）**：apps/console 经 P0 契约解锁，`next build` 全路由绿 + 3030 冒烟首页/详情 200；剩余迭代：payload 字段 KPI 扩展 + 趋势图 | batch91/92 真实数据渲染正确，no-store 刷新 ≤2s |
| P2 任务闭环 | 接 `/api/tasks` 下发 + `X-Claim-Token` 头（URL 传密钥永禁——P1-S3 铁律） | 漫剧 image_to_video 从面板一键触发（复用 E2E 链路） |
| P3 编排可视化 | 漫剧六阶段状态机视图（StageStatus 五态 → 甘特/泳道），对接 `projects/{id}/state/` 快照 | 阶段4 H3 执行实时可视 |

## 六、决策记录（ADR-FE-001）

- **决策**：采用方案 A（Next.js + shadcn/ui + Tremor，静态导出）。
- **背景**：§二双阵营分析 + §三 HUB 审计 + 生产闭环 04/06 蓝图既定部署模式。
- **备选**：方案 B（若团队抗拒 Next 构建复杂度，可降级，契约/组件层完全复用）。
- **铁律继承**：契约单一事实源（P1-C2 决策）；URL 传密钥弃用（P1-S3）；纯静态只读先行，写操作走 claim（fail-closed）。
