## 第 17 章 契约体系：双端一致性的工程化

### 17.1 契约链路全景

```
packages/manifest-schema/src/index.ts      ← manifest 契约（zod 唯一真源）
packages/manifest-schema/src/batches.ts    ← batches 契约（envelope5+unit18+top10）
        │ pnpm gen（gen-json-schema.ts）
        ▼
packages/manifest-schema/schema/*.schema.json   （Draft-07 生成物，防漂移门禁对象）
        │ 消费
        ├──> validate_manifest.py     Python 写端自检（nightly 可挂）
        ├──> test-schema.ts          真实 manifest 样本冒烟（CI）
        └──> check_contract_sync.py  TS↔Python 字段差集双向校验（CI 门禁 exit 1）
```

### 17.2 字段速查

- **manifest record（17 字段）**：ref_img / seed / status / video_path / gen_seconds /
  peak_rss_gb / mps_alloc_gb / lipsync{backend,confidence,av_offset,score_norm,scored_at} /
  human{score,tags,notes}（+passthrough 放行扩展）
- **batches 单元（18 字段）**：id/time/ended/model/pipeline/refImages/seeds/success/failed/
  skipped/avgScore/maxScore/**status**/videos/defects/params/durationMin/reconciled
- **状态机**：completed | running | partial | failed（skipped 归并入判定）

### 17.3 契约变更五步流程（SOP）

```bash
# 1. 改 zod 真源（index.ts / batches.ts）
# 2. 重生成 JSON Schema
cd packages/manifest-schema && pnpm gen
# 3. 双端同步：Python 写端（export_dashboard_data/h3_common）字段清单同步
# 4. 本地门禁
pnpm test && python scripts/pipeline-tools/check_contract_sync.py
# 5. 提交 → CI 五检查（编译/契约/schema 漂移/console build/spawn 白名单）
```

### 17.4 历史坑（契约专属）

| 坑 | 教训 |
|---|---|
| `export *` 静默遮蔽 | index.ts 旧内联 schema 曾与 batches.ts 并存，删除旧内联后才可见 |
| lipsync `.nullable()` | 写端初始写 `null`，schema 外层未放行 → batch1000 首撞；nullable 字段必须显式 |
| schema 漂移 | 生成物不提交会漂移 → CI「gen 后 git diff --exit-code」锁死 |

**验收**：新增一个契约字段并走完五步流程，CI 全绿。

## 第 18 章 面板数据桥

### 18.1 唯一写端语义（export_dashboard_data.py）

- **全量幂等重建**：扫全部 `output_batch*/manifest.json` → 重建 batches.json。
  手改 batches.json 会在下次导出被「纠正」——这不是 bug 是设计（manifest 才是真源）；
- 十分制归一：`avgScore = round(score_norm × 10)`；score_scale 字段自描述刻度；
- 状态推导八分支（含 skipped 归并：仅 SKIPPED 批不算 completed——v1.2.0 修复）；
- `reconciled` 块原样透传进批次单元（面板可见收敛时间/原因/retry_hint）。

### 18.2 运维三命令

```bash
# 全量重建（夜间⑤自动；手动刷新）
/opt/miniconda3/envs/h3-m4/bin/python scripts/pipeline-tools/export_dashboard_data.py
# 入库（gitignore 规则要求 -f）
git add -f dashboard/data/batches.json
# 本地核验
python -c "import json;d=json.load(open('dashboard/data/batches.json'));print(len(d['batches']),d['score_scale'])"
```

**验收**：手改 batches.json 一个字段 → 重跑导出 → 解释为何恢复原值。

## 第 19 章 console 面板操作

### 19.1 页面与路由

| 路由 | 功能 | 要点 |
|---|---|---|
| `/` | 批次统计卡片 + 列表 | force-dynamic 跑完即见 |
| `/batches/[id]` | 批次详情 + **精评抽屉** | 人工分直写 manifest |
| `/pipeline` | 流水线触发/日志 | SSE 实时流（回放 300 行+live tail） |
| `/tasks` | 网关任务中心 | 列表/创建/详情/结果预览，10s 轮询 |

### 19.2 API 路由与鉴权三模型

| 路由 | 方法 | 鉴权 |
|---|---|---|
| /api/pipeline/run | POST/GET | Bearer 或 loopback（白名单 spawn + 单飞锁） |
| /api/pipeline/stream | GET(SSE) | loopback |
| /api/score | POST | loopback（写 manifest+刷新数据桥；曾零鉴权已补） |
| /api/tasks（/list /create） | GET/POST | loopback 读；创建走 LAN 直连网关 |
| /api/tasks/[id]（/result） | GET | result 为 mp4 流式代理（透传 404/410） |

- 密钥只存服务端（`GATEWAY_URL`/`H3_GATEWAY_API_KEY`），**浏览器永不见网关钥匙**；
- 写操作鉴权：`X-Claim-Token`（TASKS_CLAIM_TOKEN，常量时间比较）；伪造 xff 绕 loopback = 401。

### 19.3 本地跑法

```bash
cd apps/console
pnpm dev                       # 开发：http://localhost:3030 起（YYC³ 端口规约）
PAGES_EXPORT=1 pnpm build && npx serve out -l 3100   # 静态导出预览（api 已剥离）
```

### 19.4 精评实操流（面板版演进入口）

详情页 → 精评抽屉（ref+seed 定位）→ 打分+标签 → 提交（写 manifest）→ 数据桥自动刷新 →
回到第 15 章四步做分析+写回。

**验收**：完成一次面板精评并看到 batches.json avgScore 变化。

## 第 20 章 公网发布与多端访问

### 20.1 三条公网路径对比

| 路径 | 地址 | 数据时效 | 写能力 | 适用 |
|---|---|---|---|---|
| **GitHub Pages**（主） | https://h3.yyc3.top | 随 batches.json 提交触发 CI | 无（静态快照） | 团队/展示 |
| 网关 Nginx 路由 | api.0379.world/h3-dashboard/ | 手动同步 | 无 | 备用入口（doc07） |
| 单文件面板 | dashboard/HTML | 本地文件 | 无 | 离线/现存网（doc06，v1.2 蓝图） |

### 20.2 Pages CI 机制（pages.yml）

```
触发：main + dashboard/data/batches.json 变更
步骤：pnpm build（PAGES_EXPORT=1 → output:export）
      ├─ 剥离 src/app/api（公网无写）
      ├─ sed 删 force-dynamic（静态导出兼容）
      └─ 复制 public/CNAME（h3.yyc3.top）
部署 → Pages → 验证 curl -I 200
```

### 20.3 坑位

- Pages 模式下 `/api/*` 不存在——公网面板只读，精评必须内网（安全边界，非缺陷）；
- batches.json 是 CI 触发路径——**数据提交才触发公网更新**，只改代码不触发；
- CNAME 在 public/，pages.yml 复制——动 out 目录结构时注意保留。

**验收**：说出一次 batches.json 提交后公网面板的更新链路与验证命令（curl 200 + 内容 diff）。
