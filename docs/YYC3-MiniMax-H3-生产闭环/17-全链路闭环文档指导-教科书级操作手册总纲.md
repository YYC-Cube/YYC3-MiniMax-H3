## 第一篇 总纲与快速上手

### 第 1 章 系统全景与架构总览
- **目标**：10 分钟建立全局认知：谁在哪、数据怎么流、契约怎么管。
- **步骤概要**：读架构图（Mac M4 生成节点 → NAS 双分区 → ECS 网关 → console 面板四层）→
  对照资产地图（31 脚本 / 16 蓝图 / 契约包 / CI）→ 理解「manifest 单一事实源」辐射全链的设计。
- **资产锚点**：`scripts/lib/h3_common.py`（Manifest）、`packages/manifest-schema/src/`、`docs/YYC3-MiniMax-H3-生产闭环/01`。
- **验收标准**：能不看资料画出四层数据流图并说出每层的读写角色。
- **坑位**：08 号文档 `pipeline_full_run.py` 是蓝图非落地件，实际入口以 `pipeline_auto.py` 为准。

### 第 2 章 10 分钟上手：从零跑通一次生成
- **目标**：最快路径产出第一条视频，建立体感。
- **步骤概要**：激活 `h3-m4` 环境 → 单次推理 `scripts/h3_m4_ref2va.py`（自定义参考图）→
  核对产物路径与时长 → 进阶到 `scripts/batch-full/h3_pruned_ref2va_batch_resume.py` 快速试 seed。
- **资产锚点**：`scripts/h3_m4_ref2va.py`、`scripts/batch-full/` 六件套。
- **验收标准**：本地产出 832×480 mp4 且能播放。
- **坑位**：生成前确认 AC 电源 + 30GB 空闲磁盘 + GPU 无占用（`pgrep -f batch_ref2va`）。

### 第 3 章 核心概念词典
- **目标**：统一术语，消除歧义（教科书基本功）。
- **步骤概要**：逐条掌握：manifest 单一事实源 / batches.json 面板契约 / envelope / 四态状态机
  （completed|running|partial|failed）/ seed 演进闭环 / group_best / 三道防线（优雅终止→reconcile→评分告警）/ 双速制归档。
- **资产锚点**：`packages/manifest-schema/src/index.ts`（record 17 字段）、`src/batches.ts`（unit 18 字段）。
- **验收标准**：能解释「为什么人工分要写 manifest 而不是 md」（真源 vs 镜像，09-28 实测教训）。
- **坑位**：`SEED_LIST` 变量为大写且必须单行——`update_seed_list.py` 依赖此格式。

## 第二篇 环境与基础设施

### 第 4 章 本机生产环境（Mac M4 128GB）
- **目标**：环境可复现搭建 + 已知环境陷阱清单。
- **步骤概要**：conda `h3-m4` 环境 → 模型权重位置 → ffmpeg（homebrew）→ 性能基线
  （3.9h/seed、RSS 水印语义）→ PATH 血泪史（cron 默认 PATH 无 homebrew → nightly v1.3.0 显式导出）。
- **资产锚点**：`scripts/lib/h3_common.py`（VramConfig/load_pipeline/PerformanceTimer）。
- **验收标准**：`env -i PATH=/usr/bin:/bin` 下 `shutil.which('ffmpeg')` 非 None（PATH 修复生效）。
- **坑位**：本机 `rm` 是依赖 dirname 的包装函数——受限 PATH 测试一律用 `/bin/rm` 绝对路径。

### 第 5 章 网络拓扑：LAN 与 Tailscale 双平面
- **目标**：理解两条到 NAS/网关的路径及各自适用场景。
- **步骤概要**：LAN `192.168.3.45`（仅同网段）vs Tailscale `100.65.172.88`（跨网，默认）
  → 网关地址策略（runner/console 默认 Tailscale，上传走 LAN 直连防 90s 499）→ ssh 别名 `yyc3-45`。
- **资产锚点**：`scripts/pipeline-tools/video_task_runner.py`（--admin-gateway 默认值）、`apps/console/src/lib/gateway.ts`。
- **验收标准**：两条路径各自的 `/health` 探活命令与预期返回。
- **坑位**：09-30「NAS 宕机」误报即 LAN 断链假象——判活先用 Tailscale IP 再下结论。

### 第 6 章 NAS 与归档基座
- **目标**：掌握双分区映射、rsync 分级策略、断链自愈。
- **步骤概要**：01 号文档映射总表 → archive_to_nas.sh 双速制（manifest 快车道实时 + 媒体慢车道断点续传）
  → `.nas_pending` 自愈队列机制 → 归档核验方法（du + 文件数）。
- **资产锚点**：`scripts/pipeline-tools/archive_to_nas.sh`、`docs/.../01-NAS自动同步配置与目录映射清单.md`。
- **验收标准**：能对任一历史批次说出 NAS 侧完整落点并实核。
- **坑位**：归档「成功」以 NAS 侧实核为准，报告 ✅ 不代表免检（05:37 报告 vs 05:30 断链矛盾案例）。

### 第 7 章 密钥与鉴权治理
- **目标**：单键现状、轮换 runbook、泄漏应急。
- **步骤概要**：X-API-Key 鉴权头（Bearer 恒 403）→ stage2 收敛实录（双写→单键、restart 不重读 env 须 `up -d --force-recreate`）→ 90 天轮换流程（doc11）→ 下次轮换 2026-12-25。
- **资产锚点**：`docs/.../09-公网访问的鉴权配置.md`、`11-密钥自动轮换脚本.md`。
- **验收标准**：能在测试环境完成一次模拟轮换四步验证（新 200/旧 403/伪 403/无 401）。
- **坑位**：网关容器名 `0379-world-gateway-1`（勿误用 worker 容器）；改 .env 必须 force-recreate。

## 第三篇 每日生产 SOP（核心篇）

### 第 8 章 单次生成与调参
- **目标**：按需选择 NF4/Pruned × Ref2VA/FL2VA 四象限，掌握参数语义。
- **步骤概要**：质量档（preview/full）→ seed 语义与确定性（同图同 seed = 逐位相同产物，
  六批次实证）→ 断点续跑语义（SUCCESS 跳过、FAILED/SKIPPED 重跑）→ batch-full 六件套选型。
- **资产锚点**：`scripts/batch_ref2va_nf4.py` v1.2.0（SIGTERM 优雅终止）、`scripts/batch-full/`。
- **验收标准**：能对同一任务说出用哪个脚本、哪个档位、预期耗时。
- **坑位**：seed 间 `torch.mps.empty_cache()` 已内置（防 ~15GB 串行缓存累积）；MPS 扩散期
  0% CPU/RSS 冻结/无日志是正常表象，看 raw 日志进度条为准。

### 第 9 章 夜间批量流水线全解（nightly_run.sh v1.4.0）
- **目标**：逐 stage 吃透编排器，具备值守与排障能力。
- **步骤概要**：窗口硬约束（22:00-08:00）→ ⑥ 并发守卫（pipeline_auto/batch_ref2va 存活即拒绝，
  H3_FORCE 不豁免）→ caffeinate re-exec → ①-⑤ 逐 stage（生成→评分→归档→收敛→面板）→
  报告命名 `nightly_YYYYMMDD_b{batch|auto}.md` → 低电量/PATH/ffmpeg 三层自保 → cron 安装行。
- **资产锚点**：`scripts/pipeline-tools/nightly_run.sh`（头注释含 4 起事故加固记录与 cron 示例）。
- **验收标准**：能背出五 stage 顺序与各自失败时的表现（exit 码/报告标记）。
- **坑位**：09-29 cron 盲启撞车事故 → 守卫根治；报告 `>` 覆盖事故 → 按批次命名根治。

### 第 10 章 一键流水线 pipeline_auto
- **目标**：掌握 ①生成 ②评分 ③人工精评 ④分析 ⑤写回 的手动/自动两种用法。
- **步骤概要**：`--batch N`（指定批）/ `--auto`（夜批无人工干预模式）/ `--dry-run`（预演）→
  逐 stage 的输入输出与失败传播 → 与 nightly_run 的分工（编排 vs 执行）。
- **资产锚点**：`scripts/pipeline-tools/pipeline_auto.py`。
- **验收标准**：白天手动续跑一个 partial 批次的完整命令能一次写对。
- **坑位**：`AUTO_AFTER_GENERATE=False` 时 ③ 暂停等人工打分——夜批 auto 模式的推荐清单为 `[]` 属设计内。

### 第 11 章 网关任务队列与 Mac runner（第五能力）
- **目标**：理解交互式任务（面板提交）与夜间批量（cron）双通道及其互斥。
- **步骤概要**：任务四态（queued→running→succeeded/failed + 租约过期回收=anew 语义）→
  runner 夜窗领取/白名单防投毒/双网关地址策略 → 与批量互斥铁律（`batch_busy()` 强制等待）→
  dry-run 模式（2 秒样片走全生命周期，零 GPU 成本 e2e）。
- **资产锚点**：`scripts/pipeline-tools/video_task_runner.py`、网关 `video_tasks.py`（0379-World 仓）。
- **验收标准**：能用 `H3_FORCE=1 --once --dry-run` 完成一次全生命周期演练。
- **坑位**：runner 的互斥/窗口铁律在 runner 内，nightly 侧靠 ⑥ 守卫——两层各自独立，缺一不可。

### 第 12 章 晨检 SOP
- **目标**：3 分钟判定昨夜成败，异常时 10 分钟定位。
- **步骤概要**：五查清单：① `logs/nightly_*_b*.md` 五 stage 全绿 ② manifest 双 SUCCESS + ended_at
  ③ 评分 syncnet 非 heuristic ④ NAS 归档实核 ⑤ 面板批次状态 → 判定表（全绿/部分/失败各自动作）→
  补跑与续跑命令。
- **资产锚点**：`reconcile_batches.py --check`、`export_dashboard_data.py`。
- **验收标准**：对任一历史批次（batch1000~1005）能说出当时晨检应有的判定。
- **坑位**：score_norm=None + exit 0 的旧静默失败模式已被 v1.2.0 告警根治；见到 heuristic 降级先查 ffmpeg。

## 第四篇 质量闭环与 seed 演进

### 第 13 章 评分体系
- **目标**：读懂 conf/av_offset/score_norm/human 四层分数。
- **步骤概要**：SyncNet 优先 + heuristic 降级双后端 → conf 相对基线（480×832 域 1.5~2 常态，
  经验带 <1 差 / 1~3 中 / >3 良，勿对标官方 demo 的 ≈10）→ av_offset 系统性偏移（-11/-15 帧，
  质量杠杆所在，修复实验零 GPU）→ 人工分 manifest 真源（`set_human` API）+ md 镜像。
- **资产锚点**：`scripts/score_lipsync.py` v1.2.0、`h3_common.py`（extract_audio_wav PATH 自防御）。
- **验收标准**：能对任一 conf 值给出带依据的质量分级与下一步动作。
- **坑位**：只填 md 表格的人工分无效——必须进 manifest（09-28 实勘确认的文档缺口）。

### 第 14 章 分析与推荐（analyze_report.py）
- **目标**：从分析报告到推荐清单的推导规则。
- **步骤概要**：manifest 优先/legacy 兼容加载 → 客观/主观分对照 → 耗时基线 →
  group_best 推荐规则（每参考图严格更优，同分先到先得）→ 推荐清单空/非空语义。
- **资产锚点**：`scripts/pipeline-tools/analyze_report.py`。
- **验收标准**：给定一批分数能手工推出推荐清单并解释取舍。
- **坑位**：夜批（无人工打分）推荐 `[]` 是设计内——写回层靠空守卫兜底。

### 第 15 章 seed 写回与演进策略
- **目标**：人工在环路的最后一环：把评分变成下一批的种子。
- **步骤概要**：update_seed_list v1.2.0 全解（路径解析/大小写+行首锚定正则/空守卫/显式退出码）
  → 收敛 vs 探索策略决策框架（确定性生成使同图重跑零信息；探索预算应投向新参考图）→
  演进实操（首例：batch1005 双 7 分 → SEED_LIST=[42]）。
- **资产锚点**：`scripts/pipeline-tools/update_seed_list.py`、`.bak` 备份机制。
- **验收标准**：能完整走通「打分→分析→写回→核验」四步且主脚本 diff 仅一行。
- **坑位**：v1.1.0 三重静默失效（路径过期/正则失配/失败 exit 0）——凡「stage ✅ 但效果未见」
  先怀疑静默失效，用 git diff 验证实际效果。

### 第 16 章 终态治理与三道防线
- **目标**：任何终止场景下批次都有诚实终态、可续跑。
- **步骤概要**：四态状态机 → 防线一 SIGTERM/SIGINT 优雅终止（FAILED 留痕+半成品清理+SKIPPED 补记+ended_at 必写）
  → 防线二 reconcile_batches 僵尸收敛（TaskClear 模式，ps 判活宁漏不误，08:10 兜底 cron）
  → 防线三 评分失败告警（None → stderr ⚠ + exit 1）→ 续跑语义与 retry_hint。
- **资产锚点**：`batch_ref2va_nf4.py` v1.2.0、`reconcile_batches.py`、crontab `10 8 * * *`。
- **验收标准**：能复现「kill -TERM 生成进程 → 批次 partial → 重跑只补失败 seed」全链。
- **坑位**：batch1000（SIGTERM 僵尸）vs batch1002（同因优雅收敛）对比是三防线价值的最课件。

## 第五篇 面板与数据消费

### 第 17 章 契约体系：双端一致性的工程化
- **目标**：理解 zod 真源 → JSON Schema → Python 校验 → CI 门禁的完整链条。

  双端差集门禁 → CI 五检查。契约变更流程（改真源→重生成→双端同步→门禁）。
- **资产锚点**：`packages/manifest-schema/src/`、`.github/workflows/ci.yml`。
- **验收标准**：能演示一次契约字段新增的全流程且 CI 全绿。
- **坑位**：TS `export *` 曾静默遮蔽旧内联 schema（已删）；lipsync 字段 `.nullable()` 教训。

### 第 18 章 面板数据桥
- **目标**：manifest → batches.json 的唯一写端语义。
- **步骤概要**：全量幂等重建 → 10 分制刻度归一（score_norm×10 四舍五入）→ 状态机推导

- **资产锚点**：`scripts/pipeline-tools/export_dashboard_data.py`、`dashboard/data/batches.json`。
- **验收标准**：手改 batches.json 后重跑导出能理解为何被「纠正」（幂等重建语义）。
- **坑位**：batches.json 须 `git add -f`（gitignore 规则）；CI Pages 以它为触发路径。

### 第 19 章 console 面板操作
- **目标**：日常使用面板完成观测与精评。
- **步骤概要**：四页面（主面板/批次详情/流水线/任务中心）+ 精评抽屉 → API 路由鉴权模型
  （读 loopback / 写 X-Claim-Token / 服务端持网关钥匙）→ 本地双跑法（dev 3030 / Pages export 3100）
  → SSE 实时日志流。
- **资产锚点**：`apps/console/src/app/`（4 页面 + 6 API 路由）、`lib/api-auth.ts`。
- **验收标准**：能在面板完成一次人工精评并看到 batches.json 变化。
- **坑位**：localhost 双栈歧义（::1 被占）——端口冲突时换口或显式 127.0.0.1。

### 第 20 章 公网发布与多端访问
- **目标**：面板公网可用的三条路径及选型。
- **步骤概要**：GitHub Pages（h3.yyc3.top，静态快照模式：PAGES_EXPORT=1/剥离 api/sed force-dynamic/CNAME）
  → 网关 Nginx 静态路由（doc07）→ 单文件面板（doc06，现网只读版）→ 各自更新机制。
- **资产锚点**：`.github/workflows/pages.yml`、`docs/.../06、07` 号文档。
- **验收标准**：推送 batches.json 后能说出公网面板更新时效与验证命令。
- **坑位**：Pages 模式下 api 路由被剥离——公网面板无写操作，精评须走内网。

## 第六篇 运维加固与故障手册

### 第 21 章 事故博物馆（案例教学）
