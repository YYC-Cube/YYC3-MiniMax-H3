## 第 13 章 评分体系

### 13.1 四层分数体系

| 层 | 字段 | 含义 | 生产基线 |
|---|---|---|---|
| 机评·绝对 | `lipsync.confidence` | SyncNet 原始置信度 | **1.6 上下**（420×832 域常态） |
| 机评·归一 | `lipsync.score_norm` | 归一 0-1 | ≈0.245；**None=未出分=告警** |
| 面板显示 | `avgScore` | score_norm×10 | 2.4-2.5 |
| 人工 | `human.score/tags` | 1-10 主观分 + 缺陷标签 | 精评后写入 |

### 13.2 conf 相对基线（勿跨域对标）

- 官方 demo conf≈10 的前提：正脸特写、25fps 标准裁剪。本项目 480×832、数字人生成、
  口型区占比小——**绝对值跨域不可比**；
- 本仓经验带（score_lipsync.py v1.2.0 头注）：`<1 差 / 1~3 中 / >3 良`；
- 两 seed conf 高度一致（1.6276/1.6082，方差 1.2%）是**生成稳定性正面信号**。

### 13.3 av_offset：当前质量最大杠杆 ⭐

| 证据 | 数值 | 结论 |
|---|---|---|
| batch1001-1005 全部 seed | av_offset **-11 ~ -15 帧**（0.46-0.63s） | 系统性管线签名，非 seed 特性 |
| conf 天花板 ~1.6 vs 「良」>3 | 差 2 倍 | 探索 seed 填不平，管线修复才填得平 |

**零 GPU 修复实验设计**（信息价值 > 探索 10 个新 seed）：
```bash
# 用 ffmpeg 对现有 mp4 音轨平移 ±0.5s → 重跑 score_lipsync 重评分
ffmpeg -i h3_seed_42.mp4 -itsoffset 0.5 -i h3_seed_42.mp4 -map 0:v -map 1:a -c copy test_offset.mp4
/opt/miniconda3/envs/h3-m4/bin/python scripts/score_lipsync.py --batch 1005 --force  # 对 test 产物评
# 若 conf 显著上抬 → 管线补丁让未来所有图受益
```

### 13.4 评分失败告警（v1.2.0 语义）

- syncnet 失败自动降级 heuristic（永不断流）；双后端都 None → **stderr ⚠ + 汇总 exit 1** →
  nightly ② 显式标红。杜绝 09-27「双 None 却报完成 2/2」的静默失败；
- heuristic 失败根因=ffmpeg 不可达（`extract_audio_wav` 已加 which 前置自防御）。

### 13.5 人工分实操（manifest 真源）

```python
import sys; sys.path.insert(0, 'scripts/lib')
from h3_common import Manifest
```

## 第 14 章 分析与推荐（analyze_report.py）

### 14.1 加载优先级

```
manifest.json（唯一真相） > legacy report_batch{N}.md（兼容旧批）
```

### 14.2 分析产物结构（analysis_result_batch{N}.md）

1. 客观分/主观分对照表（未打分时主观栏空，avg 以机评计）
2. 耗时基线（gen_seconds 分布，>5h 标红疑似争用）
3. 缺陷标签聚合（口型错位/黑屏/冻结帧…）
4. **【推荐最优Seed清单】**——group_best 推导，格式 "`[42, ...]`"（带反引号单行）

### 14.3 group_best 规则（精确定义）

> 每参考图取**严格更优**的 seed（分高者胜）；同分按 records 迭代序**先到先得**；
> 全部无分/无记录 → 清单 `[]`。

案例（batch1005）：42/10 双 7.0 → 先到 42 → 推荐 `[42]`。这是**收敛语义**——
与探索策略的张力见第 15.4。

### 14.4 空/非空清单的下游语义

| 清单 | update_seed_list 行为 | 场景 |
|---|---|---|
| `[]` | ⏭️ 跳过写回 exit 0（保种子表） | 夜批 auto 无人工打分（设计内） |
| 非空 | 大小写+行首锚定正则写回 SEED_LIST，.bak 备份 | 人工精评后（演进正道） |

**验收**：给定一批分数手工推 group_best 结果并与脚本一致。

## 第 15 章 seed 写回与演进策略

### 15.1 update_seed_list v1.2.0 解剖（每条都是真实事故）

| 修复点 | v1.1.0 病灶 | 后果 |
|---|---|---|
| 路径解析 | 写死旧名 `analysis_result.md` | 永远 ❌ 找不到（现名带批次号） |
| 正则 | 不匹配大写 `SEED_LIST`；无行首锚定 | 永远不命中；首修版曾误伤 main() 内赋值行（git diff 铁证抓出） |
| 退出码 | 失败仍 exit 0 | pipeline_auto 误标 ✅——stage⑤ 从未真正工作过 |
| 空守卫 | （无此概念） | 若「修好路径」直接上，夜批 [] 会**清空种子表**让次夜白跑 |

### 15.2 演进四步实操（每夜精评后 5 分钟）

```bash
# ① 打分（面板精评抽屉 或 set_human 脚本，见 13.5）
# ② 分析
/opt/miniconda3/envs/h3-m4/bin/python scripts/pipeline-tools/analyze_report.py --batch 1005
# ③ 写回
/opt/miniconda3/envs/h3-m4/bin/python scripts/pipeline-tools/update_seed_list.py --batch 1005
# ④ 核验（必须！git diff 只应有一行变化）
git diff scripts/batch_ref2va_nf4.py
ls scripts/batch_ref2va_nf4.py.bak   # 备份在（已 gitignore）
```

### 15.3 铁律：「stage ✅ 但效果未见」= 先怀疑静默失效

v1.1.0 三重静默失效的教训：**用 git diff 验证实际效果，绝不信任 ✅ 标记本身**。

### 15.4 收敛 vs 探索决策框架

```
确定性公理（同图同seed=逐位同产物）
  ├─ 同图重跑同 seed → 零信息空转 → 禁止
  ├─ 同图新 seed → 方差仅 1.2%（1.6276/1.6082），边际价值低
  ├─ 新参考图 → 每 2-seed 筛选夜（batch1004 模式）→ 真正的探索预算投向
  └─ 质量杠杆 → av_offset 管线实验（零 GPU）> 一切 seed 探索
```

首例实录（2026-10-02）：batch1005 双 7 分 → `[42]` 写回——人类在环路的演进环首次打通。

**验收**：完成一次真实演进四步；能对「为什么同图不再探索」给出三段论证。

## 第 16 章 终态治理与三道防线

### 16.1 防线架构

```
            任何终止/异常
                 │
   ┌─────────────┼──────────────────┐
   ▼             ▼                  ▼
防线一        防线二              防线三
SIGTERM/INT   reconcile          评分告警
优雅终止       僵尸收敛            None→exit1
(进程内)      (08:10 cron 兜底)   (编排层标红)
   │             │                  │
   └─────────────┴──────────────────┘
                 ▼
     批次必有诚实终态（四态之一）+ 可续跑
```

### 16.2 防线一：优雅终止实现要点

- `BatchTerminated(BaseException)`——继承 BaseException **不被种子级 except 吞掉**；
- SIGTERM+SIGINT 双装（Ctrl+C 同等优雅）；主线程守卫（importlib 调用兼容）；
- in-flight seed：半成品 mp4 删除 + FAILED 留痕；未起跑补 SKIPPED；
- `finally: manifest.finish()`——**任意路径必写 ended_at**；exit 143/130/1 可区分三种停止。

### 16.3 防线二：reconcile 算法

- 判定：`ended_at=null` **且** `ps` 精确匹配（`--batch N`）无活体 → 收敛；
- 宁漏不误：ps 查询异常时跳过该批（误杀活批比漏杀僵尸更糟）；
- **只追加** `reconciled` 块（at/status/reason/by/retry_hint），不回改原始记录；
- 幂等（重复跑无副作用）；`--check` 模式供 CI；`--apply` 08:10 cron 兜底。

### 16.4 课件案例：batch1000 vs batch1002（同一外因，两个世界）

| | batch1000（防线前） | batch1002（防线后） |
|---|---|---|
| 事件 | 08:00:53 被外部 SIGTERM | 22:23 被外部 SIGTERM |
| manifest | ended_at=null 僵尸，records 残缺 | ended_at 完整，FAILED+SKIPPED 齐全 |
| 面板 | 永久 running（假象） | partial(1/2) 诚实 |
| 恢复 | 手工考古 + 整批重跑 | 重跑同批自动只补 seed10 |

### 16.5 验收

复现全链：起 dry-run 生成 → kill -TERM → 查 manifest（FAILED/SKIPPED/ended_at/exit 143）→
重跑验证只补失败 seed → `reconcile --check` 确认 0 僵尸。
