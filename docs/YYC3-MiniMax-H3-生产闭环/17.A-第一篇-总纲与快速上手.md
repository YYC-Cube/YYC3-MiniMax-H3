## 第 2 章 10 分钟上手：从零跑通一次生成

### 2.1 前置检查（30 秒四连）

```bash
pmset -g batt | head -1                      # ① 必须AC Power
df -h / | tail -1 | awk '{print $4}'         # ② 磁盘 ≥30GB
pgrep -fl "batch_ref2va|pipeline_auto"       # ③ GPU 无占用（空输出=空闲）
pgrep -fl "video_task_runner"                # ④ runner 未在生成
```

### 2.2 单次推理（自定义参考图）

```bash
cd /Users/yanyu/YYC-Cube/YYC3-MiniMax-H3
source /opt/miniconda3/etc/profile.d/conda.sh && conda activate h3-m4
python scripts/h3_m4_ref2va.py \
  --ref ref_images/person_a.png \
  --audio <你的音频.wav> \
  --out output_smoke/test01.mp4
```

- 首跑含模型加载 ~3min（RSS 爬升至 ~11GB 属正常）；生成 124 帧（5.2s）单条约 10-15min。
- NF4 量化版在 M4 128GB 上是生产默认（质量/显存平衡）。

### 2.3 产物核对

```bash
ffprobe -v error -select_streams v:0 -show_entries \
  stream=width,height,r_frame_rate,nb_frames -of csv=p=0 output_smoke/test01.mp4
# 生产基线：832x480, 24/1, 124
```

### 2.4 进阶：快速试 seed（Pruned 档）

```bash
python scripts/batch-full/h3_pruned_ref2va_batch_resume.py   # 断点续跑 + seed 日志
```

选型逻辑见第 8 章四象限表。

### 2.5 坑位速查

| 症状 | 原因 | 处置 |
|---|---|---|
| 卡模型加载 0% CPU | MPS 首次 shader 编译 | 等；第二次起显著加快 |
| ffmpeg not found | 终端 PATH 缺 homebrew | `export PATH="/opt/homebrew/bin:$PATH"` |
| rm 报 command not found: found | rm 是 dirname 依赖的包装函数 | 用 `/bin/rm` |
| 生成极慢 1000s+/it | 有并行 MPS 进程争用 | `pgrep -f batch_ref2va` 查杀/等待 |

**验收**：产出一条 832×480×124 帧 mp4 且 ffprobe 四值全对。

## 第 3 章 核心概念词典

> 规则：每词 = 定义 + 为什么存在 + 锚点。概念不对，操作必错。

| 术语 | 定义 | 为什么 | 锚点 |
|---|---|---|---|
| **manifest.json** | 单批次唯一事实源：records[]（ref/seed/status/产物/性能/lipsync/human）+ 批次元数据 | 一切下游（评分/分析/面板/归档）都从它派生，杜绝双源漂移 | `h3_common.py::Manifest` |
| **batches.json** | 面板数据契约（envelope 5 字段 + 批次单元 18 字段 + top10） | 跨 TS/Python 双端消费，需独立 schema | `packages/manifest-schema/src/batches.ts` |
| **envelope** | batches.json 外层：schema_version/generated_at/score_scale/batches/top10 | 版本化 + 刻度自描述 | 同上 |
| **四态状态机** | completed \| running \| partial \| failed | 诚实表达批次终态（1000 事故前只有前两态，僵尸批次无处安放） | `export_dashboard_data.py` |
| **seed 演进闭环** | 生成→评分→人工精评→分析→group_best→写回 SEED_LIST→下一批 | 让流水线自优化；人类只在精评一环介入 | 第 13-15 章 |
| **group_best** | 每参考图取严格更优的 1 个 seed；同分先到先得 | 收敛语义；确定性生成下同图重跑零信息 | `analyze_report.py` |
| **三道防线** | ①SIGTERM 优雅终止 ②reconcile 僵尸收敛 ③评分失败告警 | 任何终止/异常场景批次都有诚实终态 | 第 16 章 |
| **优雅终止** | batch_ref2va v1.2.0：SIGTERM→FAILED 留痕+半成品清理+SKIPPED 补记+ended_at 必写，exit 143 | 区分「被停」与「崩溃」；续跑有据 | `batch_ref2va_nf4.py` |
| **reconcile** | ended_at=null 且 ps 判活无进程 → 追加 reconciled 块收敛为 partial/failed；只追加不回改 | SIGKILL/断电兜底；保留原始事实 | `reconcile_batches.py` |
| **双速制归档** | manifest 快车道实时 + 媒体慢车道 rsync 断点续传；失败写 .nas_pending 自愈 | 大媒体不阻塞闭环，断链可恢复 | `archive_to_nas.sh` |
| **窗口** | 夜间 22:00-08:00 硬约束（NIGHT_END=08） | 白天让位人工；窗口内电源/资源稳定 | `nightly_run.sh` |
| **并发守卫** | pipeline_auto/batch_ref2va 存活即拒绝起跑，H3_FORCE 不豁免 | 根治 cron 盲启撞车（09-29 事故④） | `nightly_run.sh` v1.4.0 |
| **human 真源** | 人工分必须写 manifest（set_human API）；md 表格仅镜像 | analyze 只读 manifest——只填 md 无效（实测教训） | `h3_common.py::set_human` |
| **score_norm** | conf 归一到 0-1 的分（面板 ×10 显示） | 跨后端可比；None=未出分=告警 | `score_lipsync.py` |
| **av_offset** | 音画偏移帧数（负=音频滞后） | 当前 -11/-15 帧系系统性签名，质量最大杠杆 | 第 13 章 |
| **dry-run** | 2 秒样片走全生命周期，零 GPU | e2e 验证不烧 4 小时 | runner/pipeline_auto `--dry-run` |
| **租约回收** | 网关任务 running 超时自动回收，attempts<2 重排队 | runner 崩溃任务不丢（=数字人 anewTask 语义） | 网关 video_tasks.py |
| **确定性生成** | 同图同 seed = 逐位相同产物（六批次 md5/conf 双证） | 决定演进策略：同图重跑无意义 | 第 15 章 |
| **SCORE_SCALE** | 面板十分制（score_norm×10） | 人读友好；契约字段 score_scale 自描述 | `export_dashboard_data.py` |

**验收**：能对任一术语回答「是什么/为什么/在哪」三连；特别是能讲清
「为什么人工分写 md 无效」「为什么四态缺一不可」（用 batch1000/1002 对比）。
