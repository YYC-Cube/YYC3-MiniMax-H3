## 第 21 章 事故博物馆（案例教学）

> 每例六段：现象 → 误导性表象 → 根因 → 修复 → 验证 → 规约。
> 原始记录：`nightly_run.sh` 头注释、`docs/YYC3-MiniMax-H3-impl-expert-20260925/02-执行日志`。

### 事故① cron PATH 静默失败（09-27 夜，batch1001）

- **现象**：手动评分 syncnet 直出；夜批自动评分 heuristic + score_norm=None。
- **误导性表象**：报告显示「完成 2/2 条评分」+ exit 0——失败被当成功。
- **根因**：cron 默认 PATH 无 homebrew → ffmpeg 不可达 → extract_audio_wav 静默 False →
  双后端全 None；评分器又把 None 当正常。
- **修复**：nightly v1.3.0 显式 export PATH；score_lipsync None → ⚠ + exit 1；
  h3_common which 前置自防御。
- **验证**：`env -i PATH=/usr/bin:/bin` 复现 None；修后同环境出分 + exit 0。
  生产首验：batch1004/1005 自动直出 syncnet。
- **规约**：**失败必须可观测**——任何「完成了 N 条」的统计必须先回答「有没有失败的」。

### 事故② 休眠冻结（09-17，拔电注入）

- **现象**：夜批跑到一半系统休眠，批次挂死。
- **根因**：合盖/断电触发睡眠；无 caffeinate 保护。
- **修复**：nightly 用 caffeinate re-exec 全程保活 + AC 电源门禁（非 AC 拒启）。
- **规约**：长任务三件套 = caffeinate + 电源检查 + 窗口约束。

### 事故③ CI 中文路径 quotePath（09-26，0379 仓部署脚本）

- **现象**：`git diff --name-only | grep ^docs/` 不匹配——但 docs 显然变了。
- **误导性表象**：输出里明明有 `"\346\226\207..."` 开头的路径（转义中文）。
- **根因**：git 默认 core.quotePath=true 把非 ASCII 路径转义，`^docs/` 失配。
- **修复**：两个重建入口统一 `git -c core.quotePath=false diff --name-only`。
- **规约**：凡 git 程序化消费路径输出，先想 quotePath。

### 事故④ cron 盲启撞车 + 报告覆盖（09-29 夜，双 seed10 同殁）

- **现象**：手动续跑 batch1002（20:37）后，22:00 cron 盲启 batch1003 → 双流水线争 MPS
  → 次日 11:55 两个 seed10 相隔 5 秒双双 FAILED；且 nightly_20260929.md 被 cron 覆盖。
- **误导性表象**：runner 有 GPU 互斥铁律 → 以为 nightly 也自动让路（它没有）。
- **根因**：nightly 无并发守卫；报告名 `nightly_YYYYMMDD.md` 同日互相 `>` 覆盖。
- **修复**：v1.4.0 ⑥ 并发守卫（存活即拒，H3_FORCE 不豁免）+ 报告按批次命名。
- **验证**：隔离双向验证（活体→拒/无→放）；生产实战：batch1005 夜 22:00 cron 被精确拒绝留痕。
- **规约**：编排层互斥与消费层互斥是**两层独立防线**，缺一不可。

### 附案④+ 守卫测试走火（10-01 16:50）

- **现象**：守卫测试的诱饵进程（`<<<` heredoc 瞬退）在守卫检查时已消失 → 守卫放行 →
  测试命令整体执行真实拉起 batch1005（H3_FORCE 白天跑）。
- **修复**：诱饵必须保活（注释式 cmdline sleep）；**编排脚本守卫测试禁止整体执行，只做隔离验证**。
- **收获**：顺势让 batch1005 跑完（设备空闲），获得 v1.4.0 全链实战数据——事故也是养料。

### 附案⑤ 「NAS 宕机」误报（09-30）

- **现象**：192.168.3.45 ping 不通，runner 全灭，判 P0。
- **根因**：仅 LAN 断；Tailscale 面全通（uptime 2 天），归档走 ssh 别名照常成功。
- **规约**：判活先 TS 后 LAN（第 5.3）；硬编码 LAN IP 只允许出现在策略性默认值。

## 第 23 章 监控告警与工单闭环

### 23.1 pipeline_alert 三合一（真实结构）

```bash
# 评估并 dry-run（缺省安全：不发送）
python scripts/pipeline-tools/pipeline_alert.py                # 缺省取最新有 manifest 的批次
python scripts/pipeline-tools/pipeline_alert.py --batch 1005   # 指定批
python scripts/pipeline-tools/pipeline_alert.py --send         # 真发企微 webhook
```

内部五段流水线（源码函数级）：

```
latest_batch() → assess(batch) → should_notify(state, fingerprint, severity)
    fingerprint = f"batch{N}:{severity}"          ← 聚合去重的键
    QUIET_H 静默窗：窗口内重复出现只计数不骚扰
    ESCALATE_N / severity==BLOCKED → upgraded=True ← 升级标记
  → render_markdown(a, count, upgraded) → deliver(md) → open_ticket(payload)
```

状态持久化：STATE_PATH 记录指纹计数（幂等重跑不重复轰炸）。

### 23.2 severity 判定与兜底巡检

- severity 由 assess() 产出：OK（放行）/ WARN（单 seed 失败等）/ **BLOCKED**（直接升级）；
- 定时兜底巡检扫「报告 ✅ 但 manifest 诚实」的漏网失败 → 补发告警（与晨检五查互补）；
- doc12 多节点聚合（Redis Stream）与 doc13 工单状态机为扩展层，单机生产先用本件。

### 23.3 与三道防线的衔接点

| 防线动作 | 告警联动 |
|---|---|
| 评分 exit 1（③防线） | nightly ② 标红 → 建议接 alert 通知（待接线项） |
| reconcile 收敛 failed（②防线） | retry_hint 写入 → 人工决策是否 alert |
| 优雅终止 exit 143（①防线） | 晨检判定，通常无需告警（人为场景） |

### 23.4 演练 SOP

```bash
python scripts/pipeline-tools/pipeline_alert.py --batch 998   # failed 批 → 应判非 OK
python scripts/pipeline-tools/pipeline_alert.py --batch 998 --send   # 真发一次（演练留证）
```

**验收**：完成一次 --send 演练（企微收到 + 指纹计数可见）；说出静默窗与升级阈值两个常量的作用。

### 24.2 数字人仓安全教训（2026-09-27 实勘）

- 数据库备份含**明文 DB 口令 + 真实用户数据（OSS URL/手机号关联）**——
  备份目录必须隔离 git、加密归档或销毁；在用口令应轮换；
- 规约：任何备份落盘前问三句——「有无凭据？有无 PII？gitignore 覆盖了吗？」

### 24.3 本仓红线（YYC³ + 项目沉淀）

密钥/env 真值不入文档不入提交；`X-API-Key` 非 Bearer；公网面板只读；spawn 白名单；
写端点必须鉴权（score 曾零鉴权已补——**新增路由必查**）。

**验收**：完成一次月报生成；能对任一新 API 路由做 30 秒安全评审。
