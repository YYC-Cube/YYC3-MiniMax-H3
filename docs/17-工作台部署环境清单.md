### 2.3 令牌鉴权（推荐配置；未配置仅回环放行）

| 变量 | 覆盖端点 | 校验方式 |
| ---- | ---- | ---- |
| `TASKS_CLAIM_TOKEN` | `/api/tasks/**` | `X-Claim-Token` 常量时间比较 |
| `PIPELINE_TOKEN` | `/api/pipeline`、`/api/score` | `Authorization: Bearer` |
| `H3_SESSION_KEY` | `/api/session`（私网外签发） | `X-Session-Key` 预共享密钥 |

**会话令牌机制**：SPA 启动先取 `/api/session`（私网/回环或 H3_SESSION_KEY 放行）→ 获得 HMAC-SHA256 签名 12h 令牌 → 内存持有附加到后续请求。**URL 传密钥永禁**（P1-S3 铁律延续）。

**鉴权矩阵（2026-10-05 实测）**：远程无令牌 401（fail-closed）✓ · 有效会话令牌放行 ✓ · 伪造/过期令牌拒收 ✓ · 回环直连（dev）✓ · 令牌配置后 loopback 不再豁免 ✓

## 五、发布灰度与回滚 SOP（终审遗留 P2 落地，2026-10-05）

### 5.1 灰度（预发验证）流程

GitHub Pages 为静态原子切换（无流量比例灰度），预发验证用 **ref 指定部署**替代：

```bash
# ① 功能分支构建产物预发验证（workflow_dispatch ref 输入 → 部署该 ref 的落地页）
gh workflow run pages-deploy -f ref=feat/your-branch
# ② 人工核对 h3.yyc3.top（六板块渲染/无 JS 错）
# ③ 验证通过 → 合并 main → push（paths 命中自动触发正式部署）
# ④ 回退预发：gh workflow run pages-deploy -f ref=main
```

> 可选强化（一次性 UI 配置）：Settings → Environments → `github-pages` → Required reviewers，为 deploy job 加人工审批卡点。

### 5.2 回滚通道（四选一，按场景）

| 场景 | 操作 | 耗时 |
| ---- | ---- | ---- |
| 线上坏版本 | `gh run rerun <上次成功run>` 或 `gh workflow run pages-deploy -f ref=<好commit>` | ~1min |
| 代码级回退 | `git revert <commit> && git push`（历史纯线性可逆） | ~2min |
| 批次数据异常 | `output_batch*/manifest.json.bak-*` 就地恢复（写前自动备份链） | 即时 |
| 网关密钥故障 | NAS `.env.bak-YYYYMMDD-rot` 回滚（runbook 见 0379-World 轮换文档 §六） | ~5min |
